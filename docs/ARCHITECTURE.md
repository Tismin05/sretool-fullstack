# sretool-fullstack 架构重构文档

## 一、项目概述

sretool-fullstack 是一个面向 Linux 服务器的 SRE 监控工具，专注于系统指标采集、告警通知和可观测性分析。项目采用模块化设计，支持灵活的扩展和长期维护。

## 二、技术栈（阶段1）

| 组件 | 技术 | 版本 | 说明 |
|------|------|------|------|
| HTTP 框架 | **Gin** | v1.9.x | 性能高、生态好 |
| 配置管理 | **Viper** | v1.18.x | 支持 YAML/JSON/ENV |
| 日志 | **zap** | v1.26.x | Uber 出品高性能日志 |
| 定时任务 | Go 原生 `time.Ticker` | - | 无需额外依赖 |

## 六、模块设计说明

### 6.1 配置模块 (internal/config)

- 使用 Viper 加载 YAML 配置文件
- 支持环境变量覆盖
- 提供配置热重载能力

### 6.2 HTTP 服务模块 (internal/server)

- 基于 Gin 框架
- RESTful API 设计
- 支持 WebSocket 实时推送（预留）

### 6.3 调度器模块 (internal/scheduler)

- 使用 time.Ticker 实现定时采集
- 支持可配置的采集间隔
- 管理采集生命周期

### 6.4 采集器模块 (internal/collector)

- 基于 /proc 文件系统实现
- 不依赖 gopsutil 库
- 支持 Context 取消和超时

### 6.5 告警模块 (internal/alert)

- 规则驱动告警检查
- 支持多种告警级别
- 支持邮件发送

## 九、开发约束

1. **Context 传递**: 所有 I/O 操作必须支持 Context 取消
2. **错误处理**: 使用 CollectErrors 聚合子系统错误
3. **并发安全**: 使用 Mutex 保护共享数据
4. **依赖最小化**: 优先使用 Go 标准库和 /proc 文件系统
5. **接口驱动**: 使用接口定义模块边界
